# SmartPark 사용자 여정 문서

## 1. 문서 개요

### 1.1 문서 목적

본 문서는 SmartPark 서비스의 주요 사용자가 서비스를 이용하는 전체 흐름을 정리하기 위해 작성되었다.

SmartPark는 사용자의 현재 위치와 목적지를 기반으로 주변 주차 가능 공간을 탐색하고, 곧 비워질 주차 공간 정보, 개인 주차장 공유, NFC 기반 간편 결제, AI 기반 혼잡도 분석 기능을 제공하는 AI 기반 주차난 해결 서비스이다.

본 문서는 `PERSONA.md`에서 정의한 주요 사용자 유형을 바탕으로, 사용자가 어떤 문제를 겪고 어떤 흐름으로 SmartPark를 이용하는지 정리한다. 이를 통해 이후 요구사항 정의서, 요구사항 분석서, 서비스 시나리오, 화면 흐름 설계, 테스트 케이스 작성의 근거로 활용한다.

---

## 2. 사용자 여정 작성 범위

SmartPark의 사용자 여정은 다음 세 가지 관점으로 구분한다.

| 구분        | 사용자 유형                               | 주요 목적                                                 |
| ----------- | ----------------------------------------- | --------------------------------------------------------- |
| 이용자 여정 | 일반 운전자, 일정 기반 방문 운전자        | 주차 공간을 빠르고 정확하게 찾고 이용하는 것              |
| 공급자 여정 | 개인 주차 공간 공급자, 상가 주차장 관리자 | 주차 공간을 등록하고 운영하며 수익화하는 것               |
| 관리자 여정 | 서비스 운영 관리자                        | 플랫폼의 정보 정확성, 신고, 결제, 운영 상태를 관리하는 것 |

## 3. SmartPark 전체 서비스 흐름

### 3.1 일반 이용자 기본 흐름

```text
문제 인식
→ 현재 위치 또는 목적지 입력
→ 주변 주차장 탐색
→ 주차 가능 여부 및 혼잡도 확인
→ 주차장 선택
→ 경로 안내
→ 주차 이용 시작
→ 결제 및 출차
→ 이용 내역 확인
```

### 3.2 공급자 기본 흐름

```text
주차 공간 공유 필요 인식
→ 공급자 등록
→ 주차 공간 정보 입력
→ 이용 가능 시간 및 요금 설정
→ 주차 공간 승인
→ 이용자 매칭
→ 주차 이용 확인
→ 정산 내역 확인
```

### 3.3 관리자 기본 흐름

```text
운영 이슈 확인
→ 주차장 등록 정보 검토
→ 사용자 신고 확인
→ 결제 및 이용 내역 조회
→ 문제 처리
→ 운영 통계 확인
→ 서비스 품질 개선
```

## 4.2 사용자 상황

김민준은 주말에 성수동에서 약속이 있다. 목적지 근처는 주차 공간이 부족하고, 기존 지도 앱으로 검색한 주차장은 도착했을 때 만차인 경우가 많았다.

김민준은 출발 전 또는 이동 중에 실제 주차 가능성이 높은 공간을 확인하고 싶다. 단순히 가까운 주차장보다 현재 이용 가능한지, 요금은 얼마인지, 목적지까지 얼마나 가까운지, 혼잡도는 어느 정도인지를 한 번에 비교하고 싶어 한다.

## 5.2 사용자 상황

박지현은 가족 병원 예약이 있어 오전 10시까지 병원에 도착해야 한다. 병원 주차장은 항상 혼잡하고, 만차일 경우 주변 유료 주차장을 다시 찾아야 한다.

박지현은 출발 전에 도착 예정 시간 기준으로 주차 가능성이 높은 곳을 확인하고 싶다. 또한 주차장과 병원 사이의 도보 거리까지 함께 고려하고 싶어 한다.

# 6. 사용자 여정 3: 개인 주차 공간 공급자

## 6.1 대상 페르소나

| 항목        | 내용                                               |
| ----------- | -------------------------------------------------- |
| 페르소나    | 이성호                                             |
| 사용자 유형 | 개인 주차 공간 공급자                              |
| 주요 상황   | 평일 낮에 비어 있는 개인 주차 공간을 공유하고 싶음 |
| 핵심 니즈   | 남는 주차 공간을 안전하고 간편하게 수익화하는 것   |

---

## 6.2 사용자 상황

이성호는 개인 주택에 주차 공간 1면을 보유하고 있다. 평일 낮 시간에는 주차 공간이 비어 있지만, 직접 이용자를 구하거나 결제를 관리하는 것은 번거롭다.

이성호는 앱을 통해 주차 공간을 등록하고, 이용 가능 시간과 요금을 설정한 뒤 자동으로 이용자와 연결되기를 원한다. 또한 이용자와의 분쟁, 이용 시간 초과, 무단 이용 문제를 최소화하고 싶어 한다.

## 7.2 사용자 상황

최은정은 중소형 상가 건물의 주차장을 관리한다. 건물에는 병원, 학원, 카페, 음식점이 입점해 있어 시간대별 주차 수요가 다르다. 특정 시간에는 주차 공간이 부족하지만, 일부 시간대에는 빈 주차 공간이 많다.

최은정은 주차 공간 이용 현황을 확인하고, 외부 이용 가능 시간대를 설정하여 유휴 주차 공간을 효율적으로 활용하고 싶어 한다.

## 8.2 사용자 상황

정다은은 SmartPark 플랫폼 운영을 담당한다. 주차장 공급자가 등록한 정보가 실제와 일치하는지 확인하고, 사용자 신고나 결제 오류, 허위 등록 문제를 처리한다.

SmartPark는 위치 정보, 결제 정보, 주차장 이용 정보가 함께 처리되는 서비스이기 때문에 운영 관리자의 역할이 중요하다. 허위 출차 예정 정보, 허위 주차장 등록, 결제 실패, 이용자 분쟁은 서비스 신뢰성에 직접적인 영향을 준다.

# 13. 사용자 여정 기반 UI/UX 고려사항

## 13.1 일반 이용자 화면

- 지도 화면에서 주변 주차장의 위치와 상태가 직관적으로 보여야 한다.
- 주차장 상태는 `이용 가능`, `곧 비워짐`, `혼잡`, `만차`와 같이 명확하게 구분되어야 한다.
- 주차장 카드에는 거리, 요금, 혼잡도, 운영 시간이 함께 표시되어야 한다.
- 목적지 검색 후 추천 주차장이 우선순위로 표시되어야 한다.
- 결제 화면은 이용 시간, 요금, 결제 수단, 결제 완료 상태를 명확하게 보여야 한다.

---

## 13.2 공급자 화면

- 주차 공간 등록은 단계별 입력 방식으로 구성되어야 한다.
- 위치, 사진, 요금, 이용 가능 시간 입력 항목이 명확해야 한다.
- 등록 상태는 `검토 중`, `승인 완료`, `반려`와 같이 구분되어야 한다.
- 이용 내역과 정산 내역은 공급자가 쉽게 확인할 수 있어야 한다.
- 신고 또는 문의 기능은 접근하기 쉬운 위치에 있어야 한다.

---

## 13.3 관리자 화면

- 운영 대시보드는 신고, 결제 오류, 승인 대기 건수를 우선적으로 보여야 한다.
- 주차장 승인 화면에서는 등록 정보와 검토 상태가 명확해야 한다.
- 신고 관리 화면에서는 신고 유형, 처리 상태, 관련 이용 내역이 연결되어야 한다.
- 결제 관리 화면에서는 결제 성공, 실패, 환불 상태가 구분되어야 한다.
- 운영 통계 화면은 서비스 품질 개선에 필요한 핵심 지표 중심으로 구성되어야 한다.

# 15. 정리

SmartPark의 사용자 여정은 주차 공간을 찾는 이용자, 주차 공간을 제공하는 공급자, 서비스를 관리하는 운영자의 흐름으로 구분된다.

일반 운전자와 일정 기반 방문 운전자는 빠르고 정확하게 주차 가능한 공간을 찾고자 하며, 공급자와 상가 관리자는 유휴 주차 공간을 안전하고 효율적으로 운영하고자 한다. 서비스 운영 관리자는 등록 정보, 신고, 결제, 이용 내역을 관리하여 플랫폼의 신뢰성을 유지해야 한다.

따라서 SmartPark는 단순히 주차장 위치를 보여주는 서비스가 아니라, 주차 가능성 예측, 곧 비워질 자리 안내, 개인 주차장 공유, NFC 결제, 관리자 운영 기능을 하나의 흐름으로 연결하는 스마트 주차 플랫폼으로 설계되어야 한다.
